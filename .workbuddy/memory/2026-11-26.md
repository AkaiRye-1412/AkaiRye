## RAG 检索全面失效排查（用户反馈："还是查询不到，我的python学习没有入库吗"）
- 结论：Python学习.md **已入库**（note_file 1 篇 / chunk 372 块），失效的是检索链路本身，共 4 个 bug：
  1. **embedding 配置键名不匹配**：DB 里存 `provider`，indexer._embed_texts 读 `base_url` → 恒返回 None → 一直 FTS-only 降级，chunk_vec 恒 0 行。修复：读 `base_url or provider`
  2. **向量表维度写死 1024**：真实模型 doubao-embedding-vision 是 2048 维，插入必失败。修复：indexer._ensure_vec_dim 检测声明维度不符时 DROP+重建 chunk_vec 自愈；dim 改用 len(vectors[0]) 实际值
  3. **纯中文查询被合成单个邻接短语**：phrase_expr 只按中/英边界分段，"介绍下集合"是纯中文整段 → `"介绍 绍下 下集 集合"` 要求原文紧邻 → 0 命中。修复（V3）：**每个 bigram 独立成短语后 OR**（与索引侧 token 粒度对称），跨词噪声 bigram 索引中通常不存在
  4. **代码块内 # 注释被误当标题**：chunk_note_markdown 只认 `#`/`##`，Python 教程的 ``` 代码块里 `# 注释` 行全部被当标题切块（372→碎片化，title_path 变成代码注释语义）。修复：跟踪 ``` / ~~~ 围栏，围栏内不识别标题；标题栈支持 h1..h6（title_path 如 "Python的核心语法 / 数据存储容器 / 集合set"）
- 附带增强：chunk_fts 索引内容改为 title_path + content（标题命中词频更高，bm25 排序更准）
- 接口约束（已实测）：火山 ark coding 端点 embeddings **单次 input 上限 10 条**、并发会 429 限频 → batch=10 + 批次间 0.8s 节流 + 指数退避重试（4 次）
