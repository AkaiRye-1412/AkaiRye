## 1. 设计总则

1. **Q-14 已确认**：RAG 提问走 REST（`POST /api/rag/ask`），回答 token 流经 `/ws/events` 的 `rag.stream` topic 推送；断线重连按 `message_id` 经 REST 补拉兜底；
2. 除 PDF 字节流外全部为 JSON；错误响应统一 `{error:{code,message,detail?}}`；API Key 永不出后端（脱敏规则见 api-rules 第 6.2 节）；
3. 每个 REST 资源标注对应**后端服务**（02 文档服务层）与**数据库表**（03 文档），保证"文档 ↔ 服务 ↔ 表"三方可对照。

## 3. REST 端点详细设计

> 动词语义、幂等规则、错误码均遵循 api-rules；以下仅列路径、方法、关键参数与响应要点，请求/响应完整字段以实现期 Pydantic 模型为准（与本文档双向校验）。

### 3.1 系统状态（启动自检）

| 方法 | 路径 | 说明 | 响应要点 |
|---|---|---|---|
| GET | `/api/system/status` | 前端启动时的健康检查 | 配置完整性（必备项是否已配置）、各路径有效性（vault_root/pdf_root 可访问）、索引概况（笔记/手册 ready 数）、最近备份时间、WS 可用 |

### 3.2 配置（M8 · FR-CFG）

| 方法 | 路径 | 说明 | 要点 |
|---|---|---|---|
| GET | `/api/config` | 读取全部配置（按 key 分组） | `llm.api_key`/`embedding.api_key` 脱敏为 `{api_key_set, api_key_masked}` |
| PUT | `/api/config` | 批量保存配置 | 请求体 `{key: value}` 局部更新；api_key 传空/掩码=不修改；保存后广播 `config.updated`（热生效，不重启） |
| POST | `/api/config/test-llm` | 测试 LLM 连通 | 接受与保存相同的配置体但**不落库**；返回 `{ok, latency_ms, model, error?}` |
| POST | `/api/config/test-embedding` | 测试 Embedding 连通 | 同上；成功返回实际维度 dim（供 R4 校验比对） |
| GET | `/api/brands` | 品牌列表 | FR-RAG-13 枚举 |
| POST | `/api/brands` | 新增品牌 | `{name, sort?}`；重名返回 409 |
| PATCH | `/api/brands/{name}` | 启用/禁用、调序 | `{enabled?, sort?}` |

### 3.4 项目（FR-PROJ）

| 方法 | 路径 | 说明 | 要点 |
|---|---|---|---|
| GET | `/api/projects` | 项目列表 | 由 note_file 聚合：customer/project_name/status/start_date/updated_date/笔记路径；支持 `?status=active&customer=` 过滤 |
| PATCH | `/api/projects/{path}` | 更新项目状态 | `{status: active|archived}`（FR-NOTE-09）；写入 vault 头部字段后触发增量索引 |

### 3.5 笔记（M2 · FR-NOTE）

| 方法 | 路径 | 说明 | 要点 |
|---|---|---|---|
| GET | `/api/notes` | 笔记列表 | 过滤 `?customer=&project=&status=&head_ok=&indexed_status=`；字段即 note_file 列，含展示派生字段 `note_title / summary / tags / note_mode`（v2：兼容按日卡片的 name/description/tags 口径） |
| GET | `/api/notes/{path}` | 笔记内容 | 返回 Markdown 原文 + 头部字段解析结果（head_ok、缺失字段清单）+ 展示派生字段（note_title/summary/tags/note_mode） |
| PATCH | `/api/notes/{path}/meta` | 更新头部字段 | `{customer?, project_name?, status?, start_date?, base_hash?, force?}`；只改 frontmatter（客户→`name`、项目名→`project`、状态→`进行中/已归档`），正文逐字保留；冲突语义同保存（未带 `?force` 且 hash 不符 → 409 `edit_conflict`）；缺 `status` 的卡片自动补写该键 |
| POST | `/api/notes` | 新建售后记录 | `{customer, project_name, start_date?, template?}`；按命名规范生成文件路径（唯一真相源落 vault）；重名返回 409 `path_conflict`；成功返回创建的笔记 |
| PUT | `/api/notes/{path}` | 保存内容 | 整体写入 Markdown（含头部字段）；**冲突语义（FR-NOTE-05）**：检测到外部修改且客户端未基于最新版本时，未带 `?force=true` 返回 409 `edit_conflict`（禁止静默覆盖）；`?force=true` = "用我的覆盖"；服务层落盘后进入 8s 防抖增量索引（FR-RAG-03/OQ-11） |
| POST | `/api/notes/{path}/save-as` | 另存副本（冲突三选之三） | `{content}` 将当前编辑内容写入新文件路径（服务层按命名规则生成不冲突路径，可传建议路径）；不动原文件（FR-NOTE-05） |
| GET | `/api/notes/{path}/history` | 外部修改检测 | 返回文件 mtime/content_hash 与缓存比对结果，供编辑器打开前冲突提示 |
| POST | `/api/notes/{path}/reindex` | 手动重建该笔记索引 | 同步触发，返回任务结果 |
| DELETE | `/api/notes/{path}` | 删除笔记（FR-NOTE-12，软删除） | 不做物理抹除：文件改名 `YYYYMMDD-HHMMSS-<原名>.md` 后移入 `{vault_root}/.trash/`（Obsidian 同名回收目录，拖回原目录即还原）；同步删除 `note_file` 缓存行与块三件套；不存在 → 404 `note_not_found`，路径越界 → 400 `path_outside_root`；返回 `{deleted, path, trashed_to, deleted_at}` |

> 新建记录的文件命名与目录规则（客户/项目目录层级）属于业务规则，实现期由 vault 服务定义，本阶段不展开。

### 3.7 手册与入库队列（M3 手册侧 · FR-RAG-04~15）

| 方法 | 路径 | 说明 | 要点 |
|---|---|---|---|
| GET | `/api/manuals` | 手册列表 | 过滤 `?brand=&status=&keyword=`；状态 8 态（含 discovered，Q-15）与 manual.status 严格一致；含 progress/error |

| POST | `/api/manuals/ingest` | 批量入库 | `{paths: [...]}`（M9 一键入库触发，路径须在 pdf_root 内）；逐个建 `ingest_task(action=ingest)`；重复提交返回既有排队任务（幂等） |
| POST | `/api/manuals/{id}/rebuild` | 触发重建 | 仅 `update`/`ready` 状态可重建（OQ-12）；新块 rebuilding 写入、旧索引保留可用 |
| POST | `/api/manuals/{id}/relocate` | 重新定位 | `{path}` 新路径；校验存在且 hash 匹配后置回 ready（仅 invalid 状态可用，FR-RAG-09） |

| POST | `/api/ingest/tasks/{id}/retry` | 重试失败任务 | 仅 failed 可重试 → 409 `state_conflict` |
| POST | `/api/ingest/tasks/{id}/cancel` | 取消排队任务 | 仅 queued 可取消 |

| 方法 | 路径 | 说明 | 要点 |

### 3.10 RAG 会话与问答（C1 / M3 · FR-RAG-16~27）

| 方法 | 路径 | 说明 | 要点 |
|---|---|---|---|
| GET | `/api/rag/sessions` | 会话列表 | 按 updated_at 倒序（FR-RAG-25） |
| POST | `/api/rag/sessions` | 新建会话 | `{title?}` 默认"新会话" |
| PATCH | `/api/rag/sessions/{id}` | 重命名 | `{title}` |
| DELETE | `/api/rag/sessions/{id}` | 删除会话 | 单事务 citation→message→session（OQ-08） |
| DELETE | `/api/rag/sessions` | 一键清空 | 同上全表；二次确认由前端负责 |
| GET | `/api/rag/sessions/{id}/messages` | 会话消息 | 含每条 assistant 消息的 citations 数组（scope/context 快照随消息返回，供回放） |
| POST | `/api/rag/ask` | **提问**（Q-14 核心） | 请求：`{session_id, question, scope}`，scope = `{mode: current|project|brand|all, customer?, project?, brands?}`（FR-RAG-17/18）；响应立即返回 `{message_id, title}` 并开始后台生成；token 流经 WS `rag.stream` 推送；完成帧 `done=true` 后引用随 REST 补拉；模型调用失败 → `model_error`，失败消息落库可见 |
| GET | `/api/rag/messages/{message_id}` | 补拉单条回答 | 含 content 全文 + citations；断线重连兜底（Q-14） |
| GET | `/api/rag/citations/{message_id}` | 回答引用明细 | source_type/source_name/chapter/page/snippet + chunk_id 溯源（断链时 `chunk_valid:false` 标记，展示仍用冗余字段） |

> **会话自动命名**：会话标题仍是默认「新会话」时，`POST /api/rag/ask` 会用本次提问内容命名（取首行、压缩空白、超 24 字截断加「…」），并在响应 `title` 字段回传新标题，前端据此直接刷新下拉里的当前会话名；用户手动改过名的会话不再自动改名（`title` 回 `null`）。标题仅作展示，不参与检索与排序口径。

## 4. WebSocket `/ws/events` 契约

topic 枚举与包络遵循 api-rules 第 3、4 节，此处明确**触发时机与 payload 细节**：

| topic | type | 触发时机 | payload |
|---|---|---|---|
| `note.changed` | event | watchdog 捕获白名单根内文件变更（防抖 + hash 去重后） | `{path, change: created\|modified\|deleted\|moved, customer?, project?}` |
| `index.updated` | event | 该笔记增量索引完成/失败/移出白名单 | `{path, indexed_status, last_error?, chunks?}` |
| `ingest.progress` | event | 队列任务状态或进度变化（≥500ms 节流） | `{task_id, manual_id, action, status, progress, error?}` |
| `manual.updated` | event | 手册状态机 8 态任一跃迁（含 discovered）（即时，不节流） | `{manual_id, status, progress?, error?}` |
| `rag.stream` | event | LLM 生成期间逐帧转发 | `{message_id, delta, done}`；`done=true` 后前端调 `GET /api/rag/messages/{id}` 取完整回答与引用 |
| `config.updated` | event | 配置保存成功（热生效广播） | `{keys: [...]}`（不含值） |
| `backup.done` | event | 每日/手动备份完成 | `{backup_id, kind, status}` |
| `context.report` | report | 前端切换当前打开笔记时上报（FR-RAG-18 自动感知） | `{path?, customer?, project?}` |

**重连对账**：重连成功后客户端依次拉取 `GET /api/system/status` → 当前页面相关资源快照（如笔记页拉 `/api/notes`、知识库页拉 `/api/manuals` + `/api/ingest/tasks`），WS 推送仅作为增量提示。

## 5. 错误码与安全

- 错误码枚举、HTTP 映射、路径越界防护、API Key 脱敏规则全部遵循 api-rules 第 5、6 节，不在此重复；
- 补充一条业务约束：`POST /api/rag/ask` 在**当前已有同会话生成中**的请求时返回 409 `state_conflict`（同会话不允许并发提问，避免上下文错乱；跨会话可并发）。
